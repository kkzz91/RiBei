## 它是什么

「日贝」是一个记账 App，但不止记账 —— 它把**钱**和**日子**放在一起：

| 板块 | 干什么 |
|---|---|
| **账本** | 记一笔账、看流水、月度预算（可自设多条金额红线）、每天花了多少、统计图、把账单分享成一张图 |
| **倒计时** | 「还有 N 天」：考试、发工资、纪念日…支持公历/农历、重复、提前提醒 |
| **待办** | 优先级、重复、逾期宽限、到点提醒 |
| **统计** | 分类占比立体饼图、分类排行、近 6 个月趋势、每天花了多少 |

**和市面上大多数记账 App 最大的区别**：它**没有一个字节发到网上**。
没有账号、没有云同步、没有统计埋点、没有广告 SDK。

## 下载安装

### 1. 下载

去 **[Releases](../../releases/latest)** 页面，下载最新那个 `日贝-vX.Y.Z.apk`。

> 每个版本的安装包都放在 Releases 里（不放进源码仓库，因为一个包 60 多 MB）。
> 官方的版本号、签名指纹在 Release 说明里都写着，可以核对。

### 2. 安装

任选一种：

- **手机浏览器/微信里直接点开** 那个 apk → 系统问「是否允许安装未知应用」→ 允许 → 安装。
- **数据线**：把 apk 拷到手机 → 用手机「文件管理」点开安装。
- **adb**（电脑上装了 Android 调试工具）：
  ```sh
  adb install -r 日贝-vX.Y.Z.apk
  ```

装的时候系统会提示「未知来源应用」，因为**这个 App 没有上架应用商店**，属于正常现象。

### 3. 更新

新版本**直接覆盖安装**就行（同一签名，数据全部保留）。

> ⚠️ **永远不要「卸载重装」**：这个 App 的数据只存在手机本地，**卸载会把账本一起删掉，且无法恢复**。
> 升级请一律「覆盖安装」。要保险的话，先到「设置 → 数据 → 数据与备份」导出一份 `.db` 备份。

## 第一次用要做的两件事

1. **走一遍首启的说明页**，其中「一键开启通知权限」建议当场就点 ——
   否则倒计时和待办**不会提醒你**。
2. 国产系统还需要你手动放行这几处（App 改不了，只能你去开）：
   - 设置 → 应用 → 日贝 → **省电策略 → 无限制**
   - 设置 → 应用 → 日贝 → **自启动 → 允许**
   - 设置 → 应用 → 日贝 → 其他权限 → **闹钟和提醒 → 允许**
   - 通知管理里允许**锁屏通知 / 悬浮通知**

   缺了「闹钟和提醒」这一项，提醒会被系统随意推迟（表现就是"经常不响"）。
   这四处设置页里也写明了，顶部还有一条常驻提示，权限被系统悄悄收回时会自动提醒你去开。

## 功能一览

**账本**
- 记一笔：自带单手数字键盘（也可切系统键盘）、10 个支出分类 + 8 个收入分类、备注、补记历史日期、支付方式（现金/微信/支付宝/银行卡/其他）
- **常用**：把一整套记账（类型+分类+金额+备注+支付方式）存下来，点一下直接落账
- **连记**：保存后不关页，连着记一串（对着小票一路记完）
- **月度预算**：设一个总额 + **自己加几条金额红线**；卡片会按你越过的条数依次变 **黄 → 橙 → 红**，超预算两成以上直接变**黑**
- **每天花了多少**：柱状图，手指按住左右滑动就看那天的金额；点进去还有一张按天表格
- **统计**：分类占比立体饼图（可点/可长按/可按住滑动）、分类排行、近 6 个月趋势柱状图
- **分享账单**：把一个月的账画成一张图，调系统分享面板发出去
- 搜索（备注/分类/金额，命中高亮）、按天分组、补记、编辑、删除

**倒计时 / 纪念日**
- 一个页面装下两种：**选过去的日子 → 纪念日（正计时）；选今天或以后 → 倒计时（带提醒）**，不用自己选类型
- 支持**公历 / 农历**（农历生日每年自动轮转，闰月已处理）
- 重复（每月/每年，自动滚到下一次）、提前 1~30 天提醒、提醒时间可设
- **详情页是一张海报**："还有/已经 N 天"，8 套背景主题（黑金/玉青/深空蓝/暖橙日暮/极简白/粉雾爱心/原木/薄荷），可分享成图
- **置顶**：只在最上面放大一张头条卡；列表通栏、一屏能看七八条
- **长按多选**：像微信那样长按进多选，批量删除

**待办**
- 优先级（低/中/高/急，高的自动置顶）、重复（每天/每周/每月）、逾期宽限（立刻/15分/…/4小时）
- 分组：已逾期 / 今天 / 明天 / 本周内 / 更晚
- 勾选时从点击处爆开一圈动画；重复项勾完推到下一周期（不消失）
- 长按多选批量删除

**其他**
- 深色模式、触感反馈（三档强度）、18 个收支分类各有专属色
- **数据与备份**：查看库文件与条数、导出一份 `.db` 备份（备份前会自动做 WAL checkpoint，保证是完整快照）
- 生日小惊喜：倒计时的名称/备注里含「生日」且当天，进 App 会有一个代码画的蛋糕 + 彩纸

## 隐私：它到底连不联网

这一点值得单独说，因为它就是这个 App 存在的理由。

- **`AndroidManifest.xml` 里没有申请 `INTERNET` 权限** —— 也就是说，从系统层面它**没有能力**联网（包括它依赖的第三方库）。
  代码里也没有任何网络请求。
- **`android:allowBackup="false"`**：连系统的云备份都不参与，数据不会被传到任何云端。
- 没有账号体系、没有崩溃上报、没有广告。
- 数据是一个本地 SQLite 文件（`ribei.db`）。你可以在「设置 → 数据与数据与备份」里看到它的路径和条数，并随时导出。
- 代价也很实在：**换手机、卸载重装都不会自动帮你恢复**。所以请定期导出备份。

## 常见问题

**Q：提醒不响 / 总是晚几分钟？**
按上面「第一次用要做的两件事」把那四处系统设置开全。国产系统的省电策略会把后台闹钟掐掉。
App 里「设置 → 提醒 → 提醒自检」会告诉你当前是哪一项没授权。

**Q：数据会丢吗？我升级之后账本空了怎么办？**
先别慌，**更不要卸载重装**。如果看到「数据读取失败」的提示，那是**读不出来**，不是数据没了 ——
数据还在盘上。先覆盖安装最新版；再不行去「设置 → 数据与数据与备份」看**记录条数**，
不为 0 就说明数据还在，导出一份 `.db` 留底。

**Q：为什么安装包这么大（60 多 MB）？**
它是 Flutter 打的**三架构通用包**（arm64-v8a / armeabi-v7a / x86_64），兼容所有手机。
按单个架构打会小一半，但那就得发好几个包、让用户自己挑。

**Q：会做 iOS 版吗？**
短期不会。除了要 Mac 和 Apple 开发者账号，还有个功能级冲突：iOS 每个 App 最多只能有 64 条待触发的本地通知，而这个 App 每个倒计时要排「提前天数 + 1」条（最多 61 条），上 iOS 得先重做通知策略。

**Q：能同步到云端 / 多设备吗？**
不能，而且这是刻意的取舍。要同步就得有服务器，有了服务器数据就不只在你手机里了。

**Q：会收费吗？**
不会。没有登录、没有内购、没有广告。如果它帮到你了，App 里有赞助入口，完全自愿。

## 从源码自己构建

环境：**Flutter 3.x**（本项目用 3.47.4 / Dart 3.13）+ Android SDK（compileSdk 36 / minSdk 24）。

```sh
git clone https://github.com/kkzz91/RiBei.git
cd RiBei

flutter pub get
flutter analyze        # 必须 No issues found
flutter test           # 必须全过（135 个）
flutter build apk --release
# 产物：build/app/outputs/flutter-apk/app-release.apk
```

> 中国大陆网络建议先设镜像：
> `FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`、`PUB_HOSTED_URL=https://pub.flutter-io.cn`。

**几个和常规 Flutter 项目不一样的地方**（都写在 `docs/接手说明.md` 里）：

- `android/gradle.properties` 里用 `org.gradle.java.home` **指到 JDK 17**，因为机器上全局的 `JAVA_HOME` 是 JDK 8。
  **换成你自己的路径**再构建。同一个文件里还有 `-Xmx3G`（低内存机器防换页）和 `-Dfile.encoding=UTF-8`（中文用户名必须）。
- **R8 压缩是关掉的**（`isMinifyEnabled = false`）：AGP 9 默认开启，实测会把通知插件里靠反射调用的类删掉。
- 发布用的签名是 **Android 标准 debug keystore**。
  ⚠️ 自己构建出来的包**签名和官方不同**，装到已装官方版的手机上会「签名不一致」装不上，
  只能卸载重装（**会丢数据**）—— 所以**自己玩可以，别发给已经在用官方版的人**。
- 数据库迁移是**幂等自愈**的（不按版本号硬加列，而是对照目标结构补齐），改库结构前请先读
  `docs/接手说明.md` 的红线 18，并跑 `python tools/check_migration_v4.py` 离线验证。

## 项目结构与文档

